# BCO layer streaming: one-step T4 qualification

This record concerns issue [#2766 part (b)](https://github.com/MakazhanAlpamys/Soup/issues/2766#issuecomment-6898294656). It qualifies BCO independently; IPO stays refused under layer streaming.

The measured source is [`2c57034a35cdd6af43673b7e5f6480bb10ea8655`](https://github.com/here-2007/Soup/commit/2c57034a35cdd6af43673b7e5f6480bb10ea8655), based on upstream `ce928294`. The final Kaggle run clones this commit without a patch. Later commits add this evidence and the changelog only. The environment record includes hashes of the wrapper, schema, task list and fixture/test sources.

## Card, stack and fixture

Kaggle Linux, one visible NVIDIA Tesla T4 (SM 7.5), driver `580.178.04`, FP16. Kaggle allocates two cards; `CUDA_VISIBLE_DEVICES=0` exposes one and the runner asserts `torch.cuda.device_count() == 1`.

Python 3.13.16; Torch `2.11.0+cu130` / CUDA 13.0; Transformers 5.20.2; TRL 0.29.1; PEFT 0.21.2; bitsandbytes 0.50.2; Accelerate 1.15.0; datasets 4.8.5. The [raw environment, rows, logs and full package freeze](evidence/bco-streaming-t4/) are retained together.

The local random Llama fixture uses seed 7, two decoder layers, hidden size 64, intermediate size 128, four attention heads, two KV heads, vocabulary 64, untied embeddings/output head, and maximum positions 128. Its FP32 source checkpoint is generated by `tests/test_v07204.py::_tiny_llama_dir`; no model is downloaded. Training uses max length 64, RAM streaming, batch 2, accumulation 1, seed 7, LoRA rank 4 / alpha 8 / dropout 0 on `q_proj` and `v_proj`, learning rate 2e-5, zero warmup, `save_steps=1`, and one optimizer step. Each CUDA batch is checked for both labels. Each cell runs in a fresh process with a 600-second timeout; NaN filtering is disabled.

- Floor stack (Transformers 5.16.1 / TRL 0.29.0): 109 passed, 4 CUDA tests skipped, including save wiring.

- Matched resident/streamed CPU loss and every LoRA gradient compare exactly with nonzero adapters and an untied head. The reference uses the same model with adapters disabled; one RAM source is constructed.
- A two-step CPU run and a run resumed from checkpoint-1 finish with identical adapters. The test inspects restored adapter tensors and nonzero `running.json` state before the resumed update.
- Five isolated mutations fail their intended test: remove untied-head refill; bypass cleanup; remove checkpoint save guard; remove final save check; double the one-row BCO budget. The unmodified tests pass. Mutation logs are retained.
- Ruff over src/tests/scripts/benchmarks and generated-reference structure checks pass. Recipe snapshots pass; no field or default changes. Exact generated reference text has two pre-existing unrelated vocabulary-description differences, so only the generated stream_layers row is refreshed.

## Attempts and remaining IPO work

The first Kaggle submission remained queued for over 40 minutes and was canceled at the user's request. Its replacement reached a T4 immediately but failed before testing because the qualification patch incorrectly marked existing files as new. The corrected patch was applied to a clean pinned checkout and every resulting file was checked against the candidate before resubmission.

Candidate version 3 passed all four BCO cells. All four IPO cells reported raw loss 25.0 and a NaN gradient norm, so IPO was excluded from the public gate. Version 4 diagnostic controls reproduced the skipped, unchanged first IPO update with the default GradScaler scale 65536 in both resident and streamed none/NF4 runs. Changing only the streamed diagnostic scale to 1024 produced finite gradients and a real update. Those diagnostic runs are explicitly unqualified; the implementation changes no loss math, precision defaults or scaler settings. A revised IPO qualification needs separate agreement.

## Reproduce

On a T4, check out the measured source and install the recorded stack. The test creates its checkpoint and tokenizer locally. Use `CUDA_VISIBLE_DEVICES=0`, `HF_HUB_OFFLINE=1`, and `HF_DATASETS_OFFLINE=1`:

```bash
PYTHONPATH=src pytest tests/test_bco_streaming.py -m gpu --no-cov -v
```

The [retained runner](evidence/bco-streaming-t4/kaggle-runner.py.txt) invokes each of the four parameterized CUDA cells separately with a 600-second timeout. CPU checks use the same file without `-m gpu` plus `tests/test_preference_dispatcher.py` and `tests/test_issue1011_streamed_save_guard.py`.
