- Fast-LoRA now keeps PEFT's dtype boundary for 4-bit base projections: only the base matmul runs in bitsandbytes' compute dtype, and its result returns to the input dtype before the LoRA add and SwiGLU/activation work. Previously the whole block input was cast to the compute dtype, which rounded the LoRA branch's input before its own cast and could push the resident NF4 parity row past the 2x criterion on some cards (#792 in #2383).
