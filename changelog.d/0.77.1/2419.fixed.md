- **Field-located config errors for wrong-typed values.** A validator that rejects a value with `TypeError` no longer escapes as `Error: TypeError: ...` with no section and no field name: the config boundary converts it to a `ValidationError`, so `soup train` and `soup plan` both print `Config validation error:` and `training -> minillm_enabled: ...`, and exit 1 instead of 2. The MiniLLM toggle message names its field rather than the release. (#2366 by @294962silent in #2419)
