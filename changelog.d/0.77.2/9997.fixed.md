- **Fixes from the review of the continual-learning loop branch** (#9997): taking over a dead holder's `loop.yaml` lock is serialised by a kernel lock and re-checks the holder, so two waiters can no longer both enter the critical section; `merge_state` never writes the iteration's stale copy (a change that does not fit what the file holds now is left out and named in the iteration notes, an unreadable file stops the daemon with a reason, `WatchAbortedError`, exit 1); `soup loop watch` logs and retries an `OSError` (a Windows permission denial, a lock timeout) instead of dying; `read_state` rides out a short Windows permission denial; `pause`, `resume`, `set`, `canary` and `rollback` print one line for a locked file (exit 1) or an invalid value (exit 2) instead of a traceback; `loop.yaml` and `iteration.json` are fsynced before the rename; the train and ship children write their output to `.soup-loops/adapters/<run>.train.log` and `.soup-loops/verdicts/<run>.ship.log` (named in `iteration.json` as `train_log` / `verify_log`) instead of holding it in memory; the loop reads the conversation records `soup serve` rotated into `serve.jsonl.<n>`; a `soup ship --gate loop-v2` verdict says in words when the held-out edits were not checked (`held-out edits not checked: N of 5 needed`, and `held_out_note` in `--output`) so a SHIP is never read as "held-out passed"; the canary's five-point boundary is exact, `strip_think` cuts at the tag, and a rating of `4.0` is read as 4.
