- `soup train --cloud runpod --cloud-submit` now talks to RunPod's REST API v2 (`https://api.runpod.io/v2`), because RunPod retired REST API v1 on 2026-11-15 and an installed `soup-cli` could no longer create a Pod. The command line and environment variables are unchanged. The Pod create body is the nested v2 body (`gpu`, `disk`, `cloud`, `entrypoint`/`cmd`); the wait reads `status` (a Pod in `ERROR` stops it with its own message) and takes the SSH address from `ssh.direct` or `runtime.ports`; a create whose response was lost is found again by walking the paginated `{"pods": [...]}` list; and a Pod record in `TERMINATED` counts as deleted. RunPod's `application/problem+json` error body (title, detail, the first three `errors`) is now shown after the HTTP status, with terminal controls and the API key removed and capped at 400 characters. An answer of HTTP 404 or 410 or a redirect for the Pod list or create is reported as one message that says RunPod has probably retired or moved the API and names `pip install -U soup-cli` and the manual path, with no Pod created or cleaned up. `/workspace` now lives on the 80 GB container disk, because v2 attaches no volume unless asked. Implemented against the published v2 reference; not exercised against the live service, which stays with #2098 (#2854 in #9999, reported by @noncalan).
