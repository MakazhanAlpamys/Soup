- **Hardening of the loop's feedback endpoint and canary** (#9998): `POST /v1/feedback` refuses a browser request whose `Origin` is not the server's own, a `response_id` the server did not issue (`404 unknown response_id`), an `edited_text` over 20000 characters, and a feedback log that reached 256 MiB (`507`, nothing appended); the serve trace and feedback logs are created owner-only on POSIX; more token shapes are redacted (GitHub, AWS, Slack, JWT, PEM keys, `api_key=...` assignments) and `user_ref` / `conversation_id` are redacted too. The canary's quality verdict counts at most 3 rated answers per conversation id and side, and a request with invalid input is no canary failure. Log lines dated more than 24 h ahead are skipped with a warning instead of freezing the data cursor. `soup loop watch --detach` claims its PID file before it spawns. `soup loop status` strips control characters from loop.yaml fields. `--adapter-dir` may not be a filesystem root, Windows UNC and drive-relative adapter paths are refused, and `soup ship` refuses pickle adapters (`--adapter`, `--base-adapter`). **Migration:** a web page posting feedback from another origin (including a dev server on another `localhost` port) is now refused with 403, so serve the UI from the server itself or post without a browser `Origin`; feedback for an unknown response id, or for an answer given before a server restart, is refused with 404; a feedback log at the size cap stops accepting posts (archive or truncate the file).
