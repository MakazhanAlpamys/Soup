- **`soup loop` deploys a canary and rolls back honestly** (#2518): the pre-wired deploy stage no longer cuts an adapter over to 100% of traffic (which also answered 404 for every newly trained adapter). It loads the adapter into the running server (`soup serve --adapter-dir`, `POST /v1/adapters/load`) and starts a canary on `soup loop init --canary-traffic` (default 5%) of keyed traffic; `soup loop watch` waits while it collects answers, promotes it at 30 healthy answers, or withdraws it on regression with production untouched. The new `soup loop rollback` returns to the version that was production before the last promotion; before any promotion it withdraws the running canary. Migration: the deploy stage now loads the adapter through `POST /v1/adapters/load`, which a server answers only when it was started with `--adapter-dir` and `--tool-auth-token` (a token is required on every bind, loopback included) — start `soup serve --adapter-dir .soup-loops/adapters --tool-auth-token <token>` and give `soup loop watch` the same token with `--tool-auth-token` or `SOUP_TOOL_AUTH_TOKEN`.
