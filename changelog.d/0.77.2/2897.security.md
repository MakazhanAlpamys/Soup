- **Hardening of `soup loop`, its state files and the loop's endpoints on `soup serve`** (#2897): taking over a dead holder's `loop.yaml` lock is serialised by a kernel lock and re-checks the holder, so two waiters can no longer both enter the critical section; `merge_state` never writes an iteration's stale copy (a change that does not fit what the file holds now is left out and named in the iteration notes, and an unreadable file stops the daemon with a reason, `WatchAbortedError`, exit 1); `loop.yaml` and `iteration.json` are fsynced before the rename and `read_state` rides out a short Windows permission denial; `soup loop watch` logs and retries an `OSError` (a Windows permission denial, a lock timeout) instead of dying; `pause`, `resume`, `set`, `canary` and `rollback` print one line for a locked file (exit 1) or an invalid value (exit 2) instead of a traceback; `soup loop watch --detach` claims its PID file before it spawns; `soup loop status` strips control characters from `loop.yaml` fields. The new `POST /v1/feedback` refuses a browser request whose `Origin` is not the server's own, a `response_id` the server did not issue (`404 unknown response_id`), an `edited_text` over 20000 characters, and a feedback log that reached 256 MiB (`507`, nothing appended); the serve trace and feedback logs are created owner-only on POSIX; more token shapes are redacted from them (GitHub, AWS, Slack, JWT, PEM keys, `api_key=...` assignments) and `user_ref` / `conversation_id` are redacted too. The canary's quality verdict counts at most 3 rated answers per conversation id and side, and a request with invalid input is no canary failure; log lines dated more than 24 h ahead are skipped with a warning instead of freezing the data cursor. `--adapter-dir` may not be a filesystem root and Windows UNC and drive-relative adapter paths are refused. The train and ship children write their output to `.soup-loops/adapters/<run>.train.log` and `.soup-loops/verdicts/<run>.ship.log` (named in `iteration.json` as `train_log` / `verify_log`) instead of holding it in memory, and the loop reads the conversation records `soup serve` rotated into `serve.jsonl.<n>`. A foreground `soup loop watch` is refused (exit 2, naming the pid and how to stop it) while a live daemon holds `.soup/loop.pid`, as `--detach` already was. A promotion the server refused ends the cycle there instead of training on top of the refused canary; a stage of the cycle that raises (a locked thumbs database, say) is recorded with its name and exception type in `last_failure` and the iteration, waits 5 minutes after the first failure and 30 after the second, is held after the third until `soup loop resume`, and no longer stops the daemon. The loop's JSONL logs (`iterations.jsonl`, `versions.jsonl`, `progress.jsonl`, `paraphrases.jsonl`, the holdout log) are created owner-only on POSIX and an older, wider one is tightened on its next append (on Windows the folder's permissions apply); the serve trace and feedback logs refuse a link put at their path after the server started; the loop's Python children start with `-P`, so a file in the project directory named like a library is not imported by them. The secret filter of `soup serve --trace-log` runs in linear time on long messages. A `soup ship --gate loop-v2` verdict says in words when the held-out edits were not checked (`held-out edits not checked: N of 5 needed`, and `held_out_note` in `--output`), so a SHIP is never read as "held-out passed". `soup ship` refuses an adapter directory whose weights are a pickle on `--adapter` and `--base-adapter` (a `.bin`, `.pt`, `.pth`, `.pkl`, `.pickle` or `.ckpt` weight file, or a pickle or zip posing as `.safetensors`); a safetensors file that is merely unreadable or truncated is still only a warning, as before. **Migration:** an adapter saved as `adapter_model.bin` worked with `soup ship` on v0.77.2 and is now refused (exit 3, `unsafe weight file (pickle / PyTorch-classic): adapter_model.bin`); re-save it as safetensors, e.g. `model.save_pretrained(path, safe_serialization=True)`, and pass that directory.
