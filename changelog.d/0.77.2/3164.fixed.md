- **A frozen LoRA base on CPU now loads float32 instead of the checkpoint's own dtype (#3164 by @Christiannilo in #3164).** `resolve_frozen_base_load_dtype` used to return `"auto"` on CPU, so a bf16-saved checkpoint loaded bf16 and every base matmul fell back to bf16 software emulation on x86 CPUs without AMX — measured 11.5x slower end-to-end (1005 s/it → 87 s/it) on a Ryzen 2600 running the TinyLlama-1.1B LoRA smoke, with val loss unchanged (1.5947 vs 1.6003). CPU training was previously documented as smoke-test-only, so the throughput cost never surfaced. CUDA and MPS resolution paths are untouched, and an explicit `dtype=` in the config still overrides the new default for memory-constrained CPU boxes.
