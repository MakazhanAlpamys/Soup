- **Layer streaming is refused under a distributed launch (#2585, #2586).** `training.stream_layers: true` used to pass when the process was launched by `torchrun`, `accelerate launch` or `deepspeed` (`WORLD_SIZE` above 1), because the DataParallel check steps aside there; nothing in the streaming runtime supports more than one process, so the run could fail late or train something other than what was asked. `soup train` now stops right after the config is loaded, and every streaming trainer setup (SFT, DPO, KTO, ORPO, SimPO) stops before any download, sharding or copying, with `distributed layer streaming is not supported yet`, the issue number and the way out (run as one process, or set `stream_layers: false`). An unset, `1` or malformed `WORLD_SIZE` is unchanged. Multi-node streaming is planned separately and will lift this guard.
