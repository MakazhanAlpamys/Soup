- `soup_cli.utils.profiler.profile_from_config`, which `soup profile --config` and the MCP `profile` tool call and which builds the train pre-flight's input (except `kbit_fp32`, which the pre-flight passes on a card without bf16 hardware), is documented as the entry point for programs that want the VRAM estimate without running `soup train`, and takes two optional arguments. `seq_len` prices that many tokens per row instead of `data.max_length`, clamped to 64 up to `data.max_length`, for a run that pads each micro-batch to its longest row (text SFT without packing, multipack, streamed data or layer streaming); any other run, and a value above `data.max_length`, is priced at `data.max_length` with `seq_len_source: "max_length"` and a note naming why, since a shorter length would under-price it. A bool or non-int raises `TypeError` and a value below 1 `ValueError`. The estimate prices rows that fill the length it is given and training data with short rows peaks far lower: Qwen3-0.6B with LoRA r16 on rows of at most 79 tokens peaked at 2108 MiB allocated and 2462 MiB on the whole card of an RTX 5070 Laptop, against 9,718 MiB (10.19 GB) estimated at `data.max_length` 1024 and 2,728 MiB at the rows' own length (`benchmarks/evidence/vram-qwen3-0.6b-realised-length.json`). The estimate alone is below the uncapped whole-card peak on three of eleven clean runs measured before #2683, so a caller keeps the pre-flight's 10% margin. That peak includes allocator cache the allocator gives back: with torch's allocator capped, the 4-bit run re-measured after #2683 trains in 1,646 MiB on the card (and fails at a 1,450 MiB cap, while the model is prepared) against an estimate of 2,003 MiB, and the one measured case where the estimate is below what a run needs is a micro-batch that fills 512 tokens (it fails at caps up to 6,000 MiB, estimate 5,930 MiB), so the margin matters most for large filled micro-batches; the docs say so. `shape` gives the model's `hidden_size`, `num_layers`, `intermediate_size`, `vocab_size` and `params` (a raw count, at least `vocab_size * hidden_size`) when its `config.json` cannot be read, so the logits term is still priced (a parameter count alone is refused); a readable `config.json` wins. The result gains `seq_len_source` and `seq_len_requested` only when `seq_len` is passed, a note for each argument, and `shape_source: "caller"` for a supplied shape; with neither argument it is unchanged. The pre-flight and `soup profile` price what they priced (#2871).
