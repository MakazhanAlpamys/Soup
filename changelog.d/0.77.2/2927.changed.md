- `soup adapters merge` scales each input's own term by its weight as of v0.78.0, where it used the weight squared: `linear`, `dare` and `svd` applied the normalised weight to both `lora_A` and `lora_B`, so `--weights 0.7,0.3` kept 0.49 and 0.09 of the two inputs' own deltas and the default equal weights kept a quarter of each of two inputs. Each factor now takes the square root of the weight, the rule `soup adapters arithmetic` uses, so the same command keeps 0.7 and 0.3, and half of each; inputs that use the same rank slots still add cross terms, and the exact weighted sum of the deltas is `soup adapters arithmetic ... --rank N`. Migration: the numbers of every `linear`, `dare` and `svd` merge of two or more inputs change (an equal-weight pair doubles each input's own term, 0.25 to 0.5), and the weights printed by an earlier `--strategy cmaes` run reproduce a different adapter, so re-run merges whose output you compare or ship. `ties` is unchanged. For adapters saved with `lora_bias=True`, `soup adapters arithmetic` without `--rank` gave the `lora_B.bias` tensor the square root of its coefficient, as if it were a factor, where the `--rank` path gave it the coefficient; both paths now give it the coefficient, so with coefficients other than 1 and -1 that bias changes on `soup adapters arithmetic`, and `soup adapters merge` keeps scaling it by the weight. Adapters without a LoRA bias give the same bytes as before (#2908 and #2935 reported and fixed by @abdulwaarith0 in #2927).
