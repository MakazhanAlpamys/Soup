- The optimizer state of an RL checkpoint (`<output>/rl-checkpoints/step-N/optimizer.pt`, read when the `pid_lagrangian` rollback restores a checkpoint) is now loaded with `torch.load(weights_only=True)`, only when `rl_checkpoint_include_optimizer` is on, and only from inside the run's output directory. A file that needs more than tensors and plain containers, or that is truncated or corrupt, is refused by name in the log and the optimizer is left as it was, instead of being loaded. A save no longer writes an optimizer state that this loader would refuse. Migration: as of v0.78.0 a checkpoint whose `optimizer.pt` holds anything other than tensors and plain containers is refused; checkpoints written by soup are plain and load as before, so delete such a file or restore from a checkpoint written by soup. A save refuses, by name in the log, a checkpoint directory that is a link leading outside the run's output directory, and writes nothing there. A `mole_gate.pt` that `soup serve --mole` or a MoLE resume cannot load with `weights_only=True` is refused by name with a `ValueError` instead of a raw traceback. A rollback with `rl_checkpoint_include_optimizer: false` restores the adapter only and no longer reads an `optimizer.pt` found in the checkpoint directory. (#2916)
