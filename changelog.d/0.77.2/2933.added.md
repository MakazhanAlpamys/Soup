- `soup ship --task-mode reward --reward-fn <accuracy|format|verifiable:math|verifiable:json_schema|path.py>` scores leg 1 with a reward function: each generated answer is scored from 0 to 1, one row per call, and the verdict is decided on the mean of the per-row numbers with the same strict rule as the other modes. A tie stays DON'T SHIP: the mean is the exact mean of the decimal numbers in the per-row file, so the same scores in another order, or scores that add up to the same decimal, never win by a rounding. A `.py` file is code and `soup ship` executes it, so it runs only when `--reward-fn` or `eval.ship.reward_fn` names it, only from under the working directory (no symlink, no network path), never on an offline `--evidence` replay, and the verdict JSON and the evidence record its name and sha256 (`task_win.reward`, `task.reward`); `verifiable:code` and `judge_rank` are refused. Anything but one finite number in [0, 1] per row is a runtime error that names the row and the side, and `--noise-floor` measures a reward run decode-only. A reward run also reports a descriptive paired summary of tuned minus base per row (`task_win.paired`, `task.paired`: the mean difference, a 95% bootstrap interval with its seed, better / worse / same, and `underpowered` when too few rows were run to support that confidence); it decides nothing and changes no verdict or exit code. This is a new opt-in setup, so no existing mode changes. The warning that `soup train` and `soup ship` print before they run a custom reward file now prints the file's path as plain text, so markup or control characters in a path cannot restyle the terminal.
