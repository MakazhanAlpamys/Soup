- **`soup train --cloud` refuses a config whose local files cannot be shipped, and ships the effective config rather than the file's text.** Both cloud backends built the remote job from the bytes of the config file, so two things were lost silently and only surfaced after the paid instance booted. A local `data.train` — which is what all 21 built-in templates set — was never uploaded, so the remote run died with `FileNotFoundError: Data file not found`; and the CLI overrides applied before the cloud branch (`--reward-hack-detector`, `--reward-hack-halt`, `--reward-hack-mitigation`, `--echo-trap-tokenizer-aware`, `--minillm-on-policy`, `--replay*`) were printed locally as enabled but were absent from the shipped config. The stub now embeds the loaded config with every override applied, and a plan naming any local input the stub cannot carry stops at plan time, naming the field and pointing at a Hub dataset id. The effective config is loaded again before anything is written, so an override combination the schema refuses (for example `--reward-hack-detector rm_ensemble` with a mitigation and the default `reward_hack_signals`, or the detector flag on an `sft` config) stops at plan time too. `--push-as` and `--gate` run locally against local files, so they are now refused with `--cloud` instead of being dropped.   **Behaviour changes:**
  - `soup train --cloud lambda|modal|runpod` on a config with a local `data.train` (or image/audio/video directory, replay set, tokenized path, reward `.py`, eval-gate suite or baseline) now exits non-zero at plan time rather than after a paid boot. Hub dataset ids and `scheme://` URIs are unaffected (the plan does not check the scheme).
  - The embedded config is the effective one, so a `--reward-hack-*` or `--minillm-on-policy` flag now takes effect on the remote run, and a flag combination that makes the config invalid is refused at plan time.
  - `--push-as` and `--gate` with `--cloud` are refused rather than silently ignored.
  - A local model path (base, teacher_model, reward_model, mole_task_adapters) is refused at plan time rather than silently shipped.

  Uploading the input files is the remaining half and is deliberately out of scope: it needs a per-backend upload path, size limits, and either an image or a volume. Refusing before the paid call is the part that can land safely today.
