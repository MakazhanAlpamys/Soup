- **A stored loss says what it is, and a run that observed no loss no longer reads as a perfect run:** `soup train` and `soup sweep` store NULL instead of a `0.0` placeholder (the completion panel prints `Loss: unavailable`, `soup runs` shows an empty cell, such a sweep arm is never ranked best), and HF's final runtime-summary log event no longer writes a metrics row carrying the last loss forward. Two nullable columns are added in place to an existing `experiments.db` (older rows read NULL): `runs.loss_summary_kind` (`per_step`, `mean` or `unavailable`) and `metrics.kind` (`train`, `eval` or `summary`), returned by `GET /api/runs/{id}`, `GET /api/runs/{id}/metrics` and the live metric event (#2589).
 Migration: `runs.initial_loss` and `runs.final_loss` (and the same fields of `GET /api/runs`) are NULL / `null` instead of `0.0` for a run that observed no loss, and HF's final summary event no longer adds a `metrics` row — read a missing loss as "no loss" rather than `0.0` in any script that reads `experiments.db` or the API, and do not expect that last extra row. Also: `log_metrics` now defaults `lr` to `None` (was `0.0`), so `GET /api/runs/{id}/metrics` can return `lr: null` for a step that logged none.
