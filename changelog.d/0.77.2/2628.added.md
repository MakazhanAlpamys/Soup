- **A pre-quantised bitsandbytes NF4 checkpoint can be imported into the layer-stream shard store byte for byte (#2628).** `soup_cli.utils.nf4_serialized.import_nf4_checkpoint()` copies the published packed weights and statistics of a double-quantised NF4 checkpoint (for example `unsloth/Qwen3-32B-bnb-4bit`) into Soup's shard layout with no dequantise or requantise step, and re-reads every shard to compare it with the source. It reads a plain checkpoint directory or a Hugging Face cache snapshot: inside a snapshot a link is followed only into the same repo's own `blobs/` directory (or the cache-wide Xet store) and any other link is refused, and with a `model.safetensors.index.json` only the files it names are read (a `consolidated.safetensors` beside them is ignored). It refuses anything it cannot carry over exactly, naming the tensor and the fix: FP4, 8-bit, non-nested, a `bnb_4bit_compute_dtype` other than bfloat16, a `llm_int8_skip_modules` list that covers a decoder projection, an unsupported block size, a mismatched shape, a corrupt scale, a truncated file. It copies in bounded 8 MiB reads and never maps a file. It is not wired into `soup train` yet, which still refuses a pre-quantised base.
