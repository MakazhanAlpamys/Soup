- `training.save_steps` and `training.logging_steps` now require a value of at least 1, like `training.eval_steps` already did (#2892 by @artikulus1301 in #2893). Neither field had a lower bound, and transformers reads a `*_steps` value below 1 as a fraction of `max_steps`, so `save_steps: 0` silently stopped saving intermediate checkpoints and `logging_steps: -1` effectively turned logging off, while `logging_steps: 0` failed only later, inside `TrainingArguments`; the MLX trainers reinterpreted the same values differently again.
