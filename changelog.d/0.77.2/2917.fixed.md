- `nan` (in any case, with or without a sign) is now refused like `inf` on the six ranged float options, `soup data validate --min-valid-fraction`, `soup draft measure --min-acceptance`, `soup data toxicity --threshold`, `soup data decontaminate --threshold`, `soup data score --threshold` and `soup data forge --uncertainty-threshold`: a usage error that names the option, with each command's usage exit code (3 for `data validate`, 2 for the others), before any input is read. Click's range check compares the value with its bounds and every comparison with NaN is false, so `nan` used to pass: the `data validate` and `draft measure` gates were off (exit 0), `data toxicity` wrote an empty file, and `decontaminate`, `score` and `forge` refused it only after reading their inputs, with exit 1. One shared check, `refuse_nan` in `soup_cli/commands/_common.py`, runs after Click's conversion on each of the six (#2906 by @Keshemir in #2917).
