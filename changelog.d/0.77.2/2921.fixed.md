- With `training.auto_mixed_precision: true`, an SFT or TTS LoRA run that picks fp16 on a card with bf16 (Qwen2, Qwen2.5, Phi-3 and Phi-3.5 on Ampere or newer) now loads its unquantized frozen base in fp16, the dtype it trains in, as it already did on a card without bf16. The base used to stay in bf16, so fp16 autocast kept an fp16 copy of every frozen weight through the step: a Qwen2.5-1.5B LoRA run peaked at 7.4 GB instead of 4.4 GB, which the VRAM pre-flight did not price. The pick is now asked once per run, so a 4-bit or 8-bit run prints "Auto mixed-precision picked" once instead of twice, and its quantized base loads and trains as before. Existing runs of this kind, including the sft and tts configs `soup autopilot` writes for those models, now store the frozen base in fp16 instead of bf16 and train with fp16 rather than fp32 hidden states, so their peak drops and their losses move slightly.
