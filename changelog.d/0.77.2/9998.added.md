- **`training.packed_lora` runs the Qwen2 QLoRA SFT step through the Triton kernels of #2623 (opt-in, CUDA, Linux) (#9998).** `soup train` checks the machine, the model's config and the settings before it loads anything, prints the memory plan, and stops with every reason and the way out (or, with `on_unsupported: stock`, says why and trains the stock step); pinned host RAM or GPU memory that is not free is refused unless `--allow-oom-attempt`. The log carries `[packed_lora]` lines and a closing `steps: N packed, M stock`; evaluation, generation, merge and save use the stock forward. `training.batch_size` must be a number, `lora.dropout` 0 and `quantization: 4bit`; `gpu_budget_mib` is a target for torch's peak memory planned from a fit, not a guarantee. On an RTX 5070 Laptop (8 GB), Qwen2.5-1.5B with the case-1 recipe trained at 3.3 times the tokens per second of plain Soup (5,184 against 1,569) with the mean loss of 105 steps within 0.04 % of plain Soup's; Qwen2.5-7B trained at a 7000 MiB budget with a torch peak of 6,650 MiB, where plain Soup's hardware-fit gate refuses the run and, forced, took about 375 s a step in system memory (record: `benchmarks/packed-lora-wired-2026-11-08.md`). Built on the Soup Kernel Challenge submission of team Luck, with ideas from teams 21, Null Pointers, DarkDaur and OrbiTeam.
