- **`soup loop` trains only when new feedback arrived** (#2531): a cycle that had just promoted a canary retrained on the same old feedback and started a new canary. Training now runs only when at least `soup loop init --min-new-pairs` (default 1) preference pairs are newer than the last training run; it still trains on all pairs collected so far, since each iteration trains a fresh adapter from the base. Two cursors in `loop.yaml` keep count: `attempt_cursor_ts` moves when a training run's verdict is decided (SHIP deployed, DON'T SHIP, or a deploy that failed for good; a skipped verdict or a deploy that will be retried keeps the batch), and the data cursor `harvest_cursor_ts` follows the version in production and moves when a canary is promoted; `soup loop status` shows the data cursor as `new_data_since`.
