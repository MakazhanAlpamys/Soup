- `soup ship` writes its audit trail: a live `--task-mode metric` or `judge_score` run with `--output verdict.json` now also writes `verdict.task-rows.jsonl` (only with `--output`; `--emit-evidence` alone writes nothing new), one JSON line per task row with the prompt, the expected text, both answers, both scores in [0, 1], whether each answer hit the token cap, whether a generation failed, and whether the row got better, worse or stayed the same, so a verdict can be checked row by row. The mean of each score column, added up left to right in `index` order and divided by the row count, is the reported `task_win.base` / `task_win.tuned` exactly for `metric` and within 1e-12 for `judge_score`, whose reported number is still the judge's own (no verdict changes); `soup_cli.utils.ship_task_rows.load_task_rows` reads the file back strictly. `--output` gains `task_rows` (the file's bare name, or `null`) and the evidence a `task_rows` pointer when it sits beside `--output`; no key is removed or renamed. The `rows` block of a `judge_score` run now classifies the rescaled scores (with or without `--output`), so on the default 1-5 scale a raw gap of 1e-9 to 4e-9 counts as the same row (display only). The file holds your prompts and answers, so it stays local: it is never part of the verdict, the evidence or the `--push` comment, it is mode 0600 on POSIX and inherits its folder's permissions on Windows, and a run killed while writing can leave a `.soup.*.tmp` file with partial rows beside it. Migration: a failed write of the file ends a SHIP with exit 1 after the verdict is written (a DON'T SHIP keeps exit 2), and these are now refused with exit 3 before any model loads, once the run is known to evaluate: an `--output` whose stem plus `.task-rows.jsonl` cannot be a file name (over 255 bytes on POSIX or 255 UTF-16 code units on Windows, so a stem of more than 239 characters that worked before), a name with a control character or, on POSIX, a backslash (use a shorter or plainer `--output` name), a network share or a device, a file of yours that the rows would replace, a `.task-rows.jsonl` file already at that path that `soup ship` did not write, and a path that cannot be examined. Migration: `soup ship` also refuses, with exit 3 and before anything is read, loaded or written, an `--output` or `--emit-evidence` that is the same file as one of the run's inputs (`--evidence`, `--task-eval` as given or taken from `--config`, `--config`, `--corrections`, `--held-out`, a `--baseline` file or the scoring-function file) or as the other output, by real path (a link, a hard link or a different case on Windows counts); `soup ship --evidence ev.json --output ev.json` used to exit 0 and replace the evidence it had just read with the verdict, and a live run replaced its task file or config the same way, so write the output to another path.
