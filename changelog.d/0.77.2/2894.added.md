- `soup ship` writes its audit trail: a live `--task-mode metric` or `judge_score` run with `--output verdict.json` now also writes `verdict.task-rows.jsonl` (next to `--emit-evidence` when there is no `--output`), one JSON line per task row with the prompt, the expected text, both answers, both scores in [0, 1], whether each answer hit the token cap, whether a generation failed, and whether the row got better, worse or stayed the same, so a verdict can be checked row by row. The mean of each score column, added up left to right in `index` order and divided by the row count, is the reported `task_win.base` / `task_win.tuned` exactly (a `judge_score` number is now built as the mean of its rescaled per-row scores, the same as before to float rounding), and `soup_cli.utils.ship_task_rows.load_task_rows` reads the file back strictly. `--output` gains `task_rows` (the file's bare name, or `null`) and the evidence a `task_rows` pointer; no key is removed or renamed and no verdict or exit code changes. The file holds your prompts and answers, so it stays local: it is never part of the verdict, the evidence or the `--push` comment. Migration: a failed write of the file now ends the run with exit 1 after the verdict is written, and an `--output` (or `--emit-evidence`) name that cannot carry the file name, that is a network share or a device, or whose `.task-rows.jsonl` file already exists and was not written by `soup ship` is refused with exit 3 before any model loads.
