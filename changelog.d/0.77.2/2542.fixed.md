- **`training.eval_gate.baseline: previous` is refused at config load instead of running the gate with no baseline (#2523, #2542).** `previous` was documented but never implemented: Soup keeps no version chain to resolve it against, so the value was read as a missing file named `previous` and the gate compared against nothing. The config field and `resolve_baseline` now refuse it in any capitalisation, with surrounding spaces or quotes, and the message names `registry://<id>` or a scores JSON file (`soup eval gate --write-baseline <file>` writes one). A file really named `previous` is still read when written as `./previous`.
