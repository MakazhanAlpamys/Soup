- `training.nvfp4` is now refused by name on any compute capability other than SM 10.0 and 10.3, the SM 12.x Blackwell cards (RTX 50-series, RTX PRO Blackwell, DGX Spark) among them, and `soup doctor` reports `NVFP4: hardware=no` there. torchao's NVFP4 backward rounds gradients stochastically (`cvt.rs`), which only SM 10.0 and SM 10.3 have, so on SM 12.x the run used to convert the model and then fail its first backward with a Triton PTX codegen error. Such a run now prints the yellow `NVFP4:` line and trains in bf16, as a pre-Blackwell card already did. SM 10.0 and 10.3 are unchanged. Migration: an NVFP4 run that trained on an SM 10.1 or 11.0 card on v0.77.2 now gets the yellow `NVFP4:` line and a bf16 run, since those capabilities were not measured.
