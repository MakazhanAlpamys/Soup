- `training.nvfp4` is now refused by name on SM 12.x Blackwell cards (RTX 50-series, RTX PRO Blackwell, DGX Spark), and `soup doctor` reports `NVFP4: hardware=no` there. torchao's NVFP4 backward rounds gradients stochastically (`cvt.rs`), which only SM 10.0 and SM 10.3 have, so on SM 12.x the run used to convert the model and then fail its first backward with a Triton PTX codegen error. Such a run now prints the yellow `NVFP4:` line and trains in bf16, as a pre-Blackwell card already did. SM 10.0 and 10.3 are unchanged. (#2867 by @abdumutalipabay0 in #2976)
