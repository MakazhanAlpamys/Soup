- **`soup ship --task-mode pairwise --output FILE` keeps the judge's verdict for every prompt** (#2626): the rows behind the win rate go to `<FILE stem>.judge-rows.jsonl`, one JSON line per judged prompt (the `--task-eval` prompts and, under `--gate loop-v2`, the held-out edits). A row carries the prompt, both answers, the `prompt_hash` key of the prompt (the 12-hex `sha256(strip().casefold())` the loop's holdout split uses), what the judge picked in each presentation order, the combined `result` and `score`, and, new in the same change: `tie_reason` on every tie (`real_tie` when the judge answered tie in both orders, `order_disagreement` when the two orders name different sides, `unreadable_reply` when a judge reply could not be parsed), `base_truncated` / `tuned_truncated` (the answer stopped at the generation token cap, as the generator reports it, not guessed from the text), and `judge_model` (the model name of `--judge-model`, never the URL). The verdict JSON gains one field, `judge_rows`, naming the rows file relative to itself, only when the rows were written. Every row carries its `schema_version`; the schema is `soup_cli/schemas/ship/judge_row.schema.json` with an example file, described in `docs/evaluation.md`. The verdict, what the judge sees and the win rate are unchanged.
