- **One peak-VRAM estimate for `soup train`'s pre-flight, `soup profile`, the MCP `profile` tool and `soup plan` (#2049 by @abdulwaarith0 in #2146).** The pre-flight and `soup profile` priced the same run with two formulas in two units, and neither charged the logits and loss chain, which decides long, large-vocabulary runs. All four now use `utils/vram_estimate.py`, which reads the model's `config.json` and safetensors headers (never the weights) and prices weights, adapters, gradients, optimizer state, activations, logits, the 4-bit dequantization copy and overhead, calibrated on 39 measured runs (`benchmarks/gate-2049-resident-vram.md`). The pre-flight now refuses some long-sequence, large-vocabulary runs and some runs without gradient checkpointing that it let through; `--allow-oom-attempt` still launches them. Tasks without an LM head (`classifier`, `reranker`, `cross_encoder`, `embedding`, `reward_model`) are charged no logits; with `use_liger` or `use_cut_ce` the logits are still charged and the output says the fused loss may not build them. `gradient_checkpointing` is priced as the trainer applies it: `auto` resolves on the card as the `sft` trainer does, `selective` is priced as no checkpointing (an upper bound), and tasks other than `sft` and `tts` checkpoint fully. `soup profile`'s numbers change, and its JSON gains the exact bytes per term, the fit verdict and where the model's shape came from. Reading a Hub model's shape can now reach the Hub from the pre-flight, `soup profile`, `soup plan` and `soup apply`, and writes its `config.json` into the Hugging Face cache, unless `HF_HUB_OFFLINE` or `TRANSFORMERS_OFFLINE` is set; the MCP `profile` tool reads only a local directory or the local cache. A Hub model with no readable `config.json` is priced from a shape guessed from its name. `soup plan` records `peak_vram_gb: null` with a `peak_vram_reason` when it cannot price the run, instead of a fixed 8.0 GB; a state file written before this still loads.
