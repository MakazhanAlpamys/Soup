- **`soup profile --model` answers whether a model fits without a `soup.yaml`, and Apple Silicon is checked against Metal's working set (#2049 by @abdulwaarith0 in #2285).** `soup profile --model <id or directory>` prices the run set by `--seq`, `--batch`, `--method lora|qlora|full`, `--lora-r`, `--optimizer` and `--gradient-checkpointing`, with the same estimate and the same bytes as a `soup.yaml` describing that run. It reads the model's `config.json` from a local directory, the Hugging Face cache or the Hub, so it works offline once the config is cached; when none can be read it exits 1 with the reason instead of pricing a shape guessed from the name. `--model` with `--config`, and the run flags without `--model`, are refused. On Apple Silicon, `soup profile` and the MCP `profile` tool now compare the estimate to Metal's recommended working-set size from mlx, not the whole unified memory, and report the memory as assumed when mlx cannot read it. The `soup train` pre-flight still skips `backend: mlx`.
