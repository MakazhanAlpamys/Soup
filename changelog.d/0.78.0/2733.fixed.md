- A bare `registry://` reference, or one with only whitespace after the scheme, no longer resolves to every registry entry, so `soup registry delete registry:// --yes` no longer deletes a lone entry; `registry://<id>`, `registry://<prefix>` and `name:tag` resolve as before. Migration: a bare `registry://` used to resolve to the only entry in the registry and exit 0 (`registry show`, `registry delete --yes`, `card`, `can pack`); it now stops with `Registry entry not found: registry://` and exits 1, so pass the entry id, a prefix of it or `name:tag`.
