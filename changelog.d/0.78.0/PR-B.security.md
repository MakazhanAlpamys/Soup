- `soup can run` now refuses a can whose config sets `output` (joined with its `experiment_name`, when it sets one) to a directory that resolves outside the working directory (an absolute path elsewhere, `..`, a symlink that leads out, a network share or a device). Such a can used to run and write its checkpoints and logs there; it now stops with exit 1 and a message that names the value. To run it, start `soup can run` from a directory that contains both the can and the output path, or take `config.yaml` out of the can, set `output` to a path under your working directory and run `soup train` on it. The confirmation panel lists the can's `output` and `data.train`, with a warning line on a local data path outside the working directory. (#PR-B)
- Every command that reads a can (`soup can inspect`, `verify`, `run`, `fork`, `publish` and `soup loop replay --extract`) now refuses, with a message that names the members, an archive that holds one name twice (in any spelling), a link, a device or a member below a file (exit 1; exit 2 for `soup loop replay --extract`). Such an archive used to be read. `soup can pack` and `soup can fork` never write one, so a can made by Soup is unaffected: rebuild any other can with one member per name (`soup can pack`, or `soup can fork` on a good copy). (#PR-B)
