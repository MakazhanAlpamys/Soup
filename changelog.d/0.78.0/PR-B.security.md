- `soup can run` now refuses a can whose config sets `output` to a path that resolves outside the working directory (an absolute path elsewhere, `..`, or a symlink that leads out), and its confirmation panel lists the can's `output` and `data.train`, with a warning line on a local data path outside the working directory. To run such a can, start `soup can run` from the directory the output should go to, or take `config.yaml` out of the can, set `output` to a path under your working directory and run `soup train` on it. (#PR-B)
- Every command that reads a can (`soup can inspect`, `verify`, `run`, `fork`, `publish` and `soup loop replay --extract`) now refuses an archive that holds two members for the same name (the same name twice, a `./` prefix, another letter case, a trailing separator), a link, a device, or a member below a file, and names the members; `soup can pack` and `soup can fork` never write such an archive. If a can you were running is refused for this, rebuild it with one member per name (`soup can pack`, or `soup can fork` on a good copy). (#PR-B)
