- `training.save_steps` and `training.logging_steps` now refuse values that cannot be a step count: a negative `save_steps`, and `logging_steps` of 0 or below (#2892 by @artikulus1301 in #2893). Neither field had a lower bound, and transformers reads a `*_steps` value below 1 as a fraction of `max_steps`, so a negative `save_steps` silently stopped saving intermediate checkpoints and `logging_steps: -1` effectively turned logging off, while `logging_steps: 0` failed only later, inside `TrainingArguments`; the MLX trainers reinterpreted the same values differently again. `save_steps: 0` stays accepted: it is the only way to switch periodic checkpoints off until #2575.

  A `soup.yaml` with a negative `training.save_steps`, or with `training.logging_steps` of 0 or below, loaded before and is now refused at load; remove the key for the default (100 and 10) or give a valid number of steps.
