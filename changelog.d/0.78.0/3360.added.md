- Expert shard storage moves into its own module, `utils/expert_shard.py`, with hardened readers and writers: the reader checks the staging buffer, the expert id, the NF4 spec pair, the expert MLP shapes and the set of tensors in the file, and closes its file handle when construction fails; the writer checks that every expert is one gate_up and down pair and that the NF4 codec output keeps its contract; the shard index is size-bounded and refuses duplicate keys (as does the safetensors header), and every shard file must resolve inside the store root. The index fields written and the format version (5) are unchanged, existing per_expert caches load as before, and an index that also carries `expert_layout_version` loads too (#3360 by @Artix6034, @kok-o)
