- `soup prune-layer-cache --model <value>` now refuses a `<value>` that can be neither a Hub id nor a path, instead of printing `Nothing to prune.` and exiting 0 (#3088 by @artikulus1301 in #3128). Two kinds were accepted before: a value that cannot be a Hub id (whitespace, a `..` segment, more than one `/`, a component that does not start with an alphanumeric or holds a character outside `A-Za-z0-9._-`, or an id longer than 200 characters), and a path-like value that does not exist (`./gone`, an absolute path). Both are refused at start-up now: `Invalid --model: ...` for the first and `Model path not found: ...` for the second, both exit 1. This is the resolution `soup bench` and `soup infer` already use (`_resolve_model_source`), plus `validate_repo_id` for the Hub-id shape.

  For a base whose directory was removed, the slot folder is named from the string alone (`model_slug`) and it is kept, so pass the Hub-id-shaped name of the slot: `model_slug` is idempotent, so `./gone` and `gone` name the same slot, and an absolute path such as `/home/u/name` is reached by its slug `home__u__name` (also a valid Hub-id shape). No slot is lost.
