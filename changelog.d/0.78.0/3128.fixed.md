- `soup prune-layer-cache --model <value>` now refuses a `<value>` that can be neither a Hub id nor a path, instead of printing `Nothing to prune.` and exiting 0 (#3088 by @artikulus1301 in #3128). Two kinds were accepted before: a value that cannot be a Hub id (whitespace, `..` anywhere in the value (`a..b`), more than one `/`, a trailing `/`, a component that does not start with a letter or digit or holds a character outside `A-Za-z0-9._-`, a component longer than 96 characters, or an id longer than 200 characters), and a path-like value that does not exist (`./gone`, an absolute path). Both are refused at start-up now: `Invalid --model: ...` for the first and `Model path not found: ...` for the second, both exit 1. This is the resolution `soup bench` and `soup infer` already use (`_resolve_model_source`), plus `validate_repo_id` for the Hub-id shape.

  For a base whose directory was removed, the slot folder is named from the string alone (`model_slug`) and it is kept, so pass the Hub-id-shaped name of the slot: `model_slug` is idempotent, so `./gone` and `gone` name the same slot, and an absolute path such as `/home/u/name` is reached by its slug `home__u__name` (also a valid Hub-id shape). A slug longer than 96 characters is reached only when one `__` in it splits it into `owner/name`, each part at most 96 characters and starting with a letter or digit; otherwise remove its folder under the cache root (`~/.soup/layer-stream` unless overridden) by hand.
