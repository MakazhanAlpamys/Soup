- **`task: moe_lora_routing` on CUDA trains its router gate on an fp32 master weight (#1266 in #1312).** The gate is the only tensor MoLE trains, and on the device `"cuda"` it was cast to bf16 with no fp32 copy for the optimizer, so its gradient and AdamW moments were bf16 as well and most AdamW steps rounded away: after 8 steps at the default `lr` (2e-5), 82.6-91.4% of the gate's weights had never moved. `"cuda:0"` kept it fp32. The gate is now fp32 on every device string and the Trainer places it with the rest of the model; the frozen base and the task LoRAs load as before. `mole_gate.pt` is saved in fp32 (`4 x hidden x adapters` bytes), and `soup serve --mole` loads it and a bf16 file from an earlier run alike. A gate trained on CUDA before this fix kept most of its initial weights, so retrain it.
