- ReLoRA restarts now follow the paper contract (#693 by @jagadeepmamidi in #1133): each fire merges the LoRA update into the base weight, reinitializes `lora_A`/`lora_B`, clears optimizer state when `relora_reset_optimizer` is set, and re-warms the learning rate. Behaviour break: `relora_steps` now requires explicit `quantization: none` because the schema default is `4bit`; previously a ReLoRA-only soup.yaml loaded and silently pruned. Embedding adapters with an empty `lora_A` are skipped; Linear LoRA is still merged even though peft puts empty embedding dicts on every LoraLayer. ReLoRA is refused at attach for `world_size > 1`, DeepSpeed, and FSDP. `relora_prune_ratio` is ignored with a warning at attach. Unsupported combos (`quantization` other than `none`, `stream_layers`, VeRA, DoRA, FSDP2 compile, MLX) are rejected at schema parse time instead of half-applying. The magnitude-prune helper now uses exact keep-count under ties. Merged base deltas remain in-memory until `soup merge` exports a dense checkpoint.
