- ReLoRA restarts now follow the paper contract (#693 by @jagadeepmamidi in #1133): each fire merges the PEFT-scaled LoRA update into the base weight, reinitializes `lora_A`/`lora_B`, prunes shape-matched tensor optimizer moments when `relora_reset_optimizer` is set, and re-warms the learning rate from `1/(W+1)` without an exact-zero step. Tied magnitudes use deterministic exact keep-count selection and scalar optimizer metadata such as `step` is preserved. Behaviour break: `relora_steps` requires explicit `quantization: none` because the schema default is `4bit`. Embedding adapters with an empty `lora_A` are skipped; Linear LoRA is still merged. The final active adapter is merged into the accumulated in-memory base and saved as a standalone dense output; `--resume` and `--hf-resume` are refused for ReLoRA because intermediate checkpoints do not encode restart history. Distributed/sharded execution remains explicitly refused.
