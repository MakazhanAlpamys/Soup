- **`training.freeze_trainable_layers` without `training.expand_layers` is now refused at config load (#1396).**
  The field was accepted on its own but read by nothing: without `expand_layers`,
  `utils/block_expansion.py` returned before looking at it, so `freeze_trainable_layers: 2`
  silently trained the whole model (or every LoRA target) instead of the top two layers.
  The error names both fields and the remedy (remove it, or set `expand_layers`);
  the field description and `docs/peft-and-efficiency.md` now say it applies only
  together with `expand_layers`.
