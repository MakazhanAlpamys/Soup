- **A judge that is down no longer costs 3 s of backoff for every row (#1522 in
  #1563).** Each judged row retried on its own, so `soup eval judge` over 10,000
  rows slept for more than 8 hours against a host that never answered, and
  `soup data from-traces --judge` did the same and then wrote an empty file
  with exit 0. An evaluator now stops asking after 3 requests in a row have
  spent their retries unanswered and raises `JudgeDownError`, a
  `JudgeUnavailableError`. `soup eval judge` prints one message naming the
  judge URL and how many items were not judged, shows the scores from before
  the outage without saving them, and exits 1; `from-traces --judge` exits 1
  and writes nothing; `soup data best-of-n` and
  `soup ship --task-mode pairwise` say how many prompts or pairs were left.
  One reply resets the count, a 4xx or an unusable reply counts as a reply, and
  a down judge is asked again after 60 s so a judge-ranked training run
  survives a short outage.
