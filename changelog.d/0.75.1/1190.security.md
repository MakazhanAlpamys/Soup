- **`soup ui` no longer keeps its auth token in `sessionStorage` or on `window._authToken` (#1136 by @mohdUwaish59 in #1190).** The Web UI now holds the token in a closure in `app.js`, and every request goes through one `authFetch` wrapper that adds the `Authorization` header without exposing the token to other page script. The token is deliberately not persisted: a reload or a new tab asks for it again (paste the token `soup ui` printed), where before it was restored from `sessionStorage`. This narrows the gap between a future rendering mistake and a token disclosure; it does not stop script already running in the page, for which the Content-Security-Policy remains the defence. The chat request no longer sends an empty `Bearer ` header when no token is held.
