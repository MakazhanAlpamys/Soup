- **`soup ab` now refuses `--alpha` + `--beta` at or above 1, where two identical arms could "reject" H0 (#1339 by @qwist1233-cpu in #1378).** Each rate was checked in (0, 1) on its own, but the reject boundary `log((1 - beta) / alpha)` stays above the accept boundary `log(beta / (1 - alpha))` only while their sum is below 1. Past that there is no `continue` band left, and because reject is tested first, every verdict in the gap rejected: `--alpha 0.6 --beta 0.5` reported `reject_h0` with `direction worse` on two byte-identical arms, and `--beta 0.95` (a power of 0.95 typed as beta) rejected a true H0 in a quarter of single looks. The command now exits 2 naming both values, and the `--beta` help plus the evaluation guide state the bound and that beta is the Type-II error rate, not the power.
- **`soup ab` names `--effect-size` instead of exiting on a bare `OverflowError` (#1339 by @qwist1233-cpu in #1378).** The drift term squares the standardised effect `--effect-size / pooled standard error`, and `**` raises `OverflowError` where `*` would return infinity, so a huge `--effect-size` ended the run on `Error: OverflowError: (34, 'Result too large')` with no flag named. The ratio is now bounded before it is squared, and the message carries the flag, the ratio and the standard error measured. Because it is the ratio that overflows, a near-constant metric column reached this at the default `--effect-size` too, and is named as well.
