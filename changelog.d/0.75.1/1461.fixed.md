- **`soup expect` refuses suite keys and argument names an expectation does not take (#1428 by @Srinivasan8888 in #1461).** `parse_suite_spec` used to read only `name` and `args` and drop every other key, and the dispatcher read arguments with `args.get(key, default)`, so the `docs/compliance.md` example (`min_tokens` / `max_tokens` beside `name`) and any misspelled argument (`max_token`) ran the expectation on its defaults and passed a 5000-token row. One table now declares each expectation's arguments and defaults; a key beside `name` is refused with "must go under `args:`", an unknown argument is refused with a nearest-name suggestion, and bounds / threshold values are checked when the suite loads, so `soup expect` exits 3 before reading any data. The `docs/compliance.md` example moves to the `args:` form, and a test reads that block from the doc and runs it against a long row.
