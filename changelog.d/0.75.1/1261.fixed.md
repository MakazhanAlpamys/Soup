- **`soup data forge --judge-provider` wrote an empty-answer row for every failed judge call and still reported "synth complete" (#1221 in #1261).** The forge judge was built without `raise_on_error`, so a connection error, HTTP 404/429/500 or malformed response came back as empty text; `score_uncertainty` rates an empty reply 1.0, so no `--uncertainty-threshold` could prune it, and the command exited 0 with a dataset that teaches a model to answer with nothing. The forge judge is now built with `raise_on_error=True` (as `soup data recipe` has been since #969); a call that fails, returns a malformed reply or returns empty text is counted and never becomes a row, whatever the threshold. The summary reports `N of M judge calls failed` with the provider, endpoint and first error; a run whose judge produced no usable row exits 1 without writing the dataset or provenance files, and a partial outage keeps the successful rows under a yellow "synth complete with judge failures" panel.
