- **`soup recipes verify` checks that a config can attach a LoRA adapter, without downloading weights (#1116 by @Srinivasan8888 in #1117).**
  It builds each base's architecture on the meta device from `config.json` alone,
  with the model class that config's trainer loads, then builds the adapter config
  the way the trainer does — `training.moe_lora` included — and runs the real peft
  attach with the config's own LoRA settings. `soup recipes verify` checks every shipped recipe,
  template and example (`--no-templates` limits it to the recipes); `--config soup.yaml`
  checks one before a long download;
  `--json` emits machine-readable rows. It exits 1 only when a config cannot
  attach. A gated repo, one needing `trust_remote_code`, or a config this
  `transformers` cannot read is reported as unverified rather than broken, and
  remote code is never executed.
