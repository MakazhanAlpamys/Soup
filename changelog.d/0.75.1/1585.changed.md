- `soup ab` now says when the accept hold is what is keeping a run at `continue`. #1419 holds `accept_h0` back while the tested rows spread more than `ACCEPT_HOLD_SPREAD_RATIO` (3) times the held-out ones, and the held-out rows are fixed — so once that hold fires on a saturated warm-up (a warm cache, or a judge that gives the same score for the first rows), no amount of extra data of the same kind releases it. The run sat at `continue` for the whole dataset with the accept rule already satisfied, while the panel printed "Insufficient evidence. Collect more samples and re-run.", advice that cannot help. A `continue` now carries `accept_held` plus the two spreads that decided it (`held_out_spread`, `tested_spread`, and `held_out_rows`), and the panel prints one line naming the ratio and what to do about it. The webhook payload gains the same four keys for a stable schema, but a held run never reaches a webhook: `accept_held=True` is only legal on a `continue`, and the webhook fires only on a terminal decision, so they are always `false` / `null` on what is sent. These are new keys only: nothing is renamed or removed, and a run that is not held carries no note at all. The accept rule itself is unchanged (#1524 by @yunaremaia in #1585).
