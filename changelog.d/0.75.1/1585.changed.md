- `soup ab` now says when the accept hold is what is keeping a run at `continue`. #1419 holds `accept_h0` back while the tested rows spread more than `ACCEPT_HOLD_SPREAD_RATIO` (3) times the held-out ones, and the held-out rows are fixed — so once that hold fires on a saturated warm-up (a warm cache, or a judge that gives the same score for the first rows), no amount of extra data of the same kind releases it. The run sat at `continue` for the whole dataset with a `log_likelihood_ratio` already past the accept boundary, while the panel printed "Insufficient evidence. Collect more samples and re-run.", advice that cannot help. A `continue` now carries `accept_held` plus the two spreads that decided it (`held_out_spread`, `tested_spread`, and `held_out_rows`), and the panel prints one line naming the ratio and what to do about it. These are new keys only: nothing is renamed or removed, so existing JSON consumers are unaffected, and a run that is not held carries no note at all. The accept rule itself is unchanged — a real fix belongs with the statistic (#1418), where a confidence sequence has no held-out prior to go stale (#1524, fixed in #1585).
