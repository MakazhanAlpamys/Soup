- **`training.use_mod: true` is refused at config load on routes that never install a Mixture-of-Depths router (#1752).** The flag was accepted on every task. Only the resident LoRA arm of the transformers SFT setup (which `tts` reaches) and the transformers pretrain setup (after its LISA/LoRA split, so LISA is included) call the router. Full fine-tuning, LISA and Spectrum on SFT, vision, audio, layer streaming, unsloth and MLX SFT all trained without one. Those requests now fail at load, naming `training.use_mod`, the task, the settings that leave the applying path, and a valid change or `use_mod: false`. Transformers SFT LoRA, TTS LoRA, pretrain LoRA and pretrain LISA still apply it. Pretrain does not inherit SFT's modality or streaming restrictions. MLX SFT is declared `rejected` in the backend-support table; the trainer still warns if it is reached. **This is a breaking change** for configs that set `use_mod: true` on a route that never applied it — that run was already training a different model than requested. `use_mod: false` and an omitted flag are unchanged, and an out-of-range `mod_capacity_factor` is still rejected by its own check.
