- **Tool-call eval scorers no longer credit a JSON number as a boolean (#1755 by @Faisal-Fayaz in #1756).** `tool_call_match` and `tool_call_args_subset` compared parsed `arguments` with Python `==`, and Python has `bool` as a subclass of `int`: a model that answered `{"enabled": 1}` where the task expected `{"enabled": true}` scored `1.0` — full credit for a wrong answer, through `score_task` and `run_eval` alike. Both are valid JSON, and they are different arguments. Arguments are now compared with a recursive `_json_equal` that rules on `bool` before anything else, so a boolean and a number never match at any depth, while numbers stay equal across forms (`1 == 1.0` still matches, as before). `tool_call_match` scores such a call `0.0`; `tool_call_args_subset` keeps its `0.5` function-name credit and gives no argument credit, so `0.5`, and its `0.5` `matched` threshold is unchanged. Scores recorded before this change can be higher than the same outputs score now, because a boolean/number substitution used to count as correct.
