- **`training.freeze_layers` / `training.freeze_ratio` did nothing on a LoRA run: the freeze was set before `get_peft_model`, which then attached a fresh trainable adapter to every targeted module in every layer, the frozen ones included (#1432 by @AmirF194 in #1494).**
  The SFT trainer now passes the layers the freeze plan left trainable to peft as `layers_to_transform`, so a frozen layer gets no adapter. On a 2-layer Llama with LoRA on `q_proj` / `v_proj`, `freeze_layers: 1` (or `freeze_ratio: 0.5`) takes the trainable LoRA parameters from 1,024 to 512 and layer 0 no longer changes. A config that sets `freeze_layers` / `freeze_ratio` together with LoRA now trains fewer layers than it did before, which is what the option always documented.
  Two related gaps closed in review: a LLaMA Pro block appended by `expand_layers` after the freeze plan was computed used to fall outside the restricted range and train with no adapter even though it was never frozen, and a list `target_modules` entry outside any numbered decoder layer (`embed_tokens`, a custom head) used to lose its adapter silently as soon as any freeze option was set.
  Shapes peft cannot restrict by layer are refused when the model is built rather than ignoring the freeze: a string `lora.target_modules` (a regex, or `all-linear`, including the value `auto` resolves to for some architectures), a list target that resolves only outside a numbered layer, `lora.target_parameters`, `lora.use_vera`, and a plan that freezes every layer. Full fine-tuning (`lora.r: 0`) is unchanged. Only the SFT text path reads these two fields.
