- **`http://[::1]:<port>` judge URLs were accepted by some gates and refused by others (#1548 in #1600).**
  The 0.75.2 outbound-endpoint hardening (GHSA-9f49-hqpf-c849, #1527) added the
  SSRF literal-IP refusal everywhere, but left each loopback allowlist as its
  own local copy. `eval/judge.py`'s `validate_judge_api_base` and
  `data/providers/vllm.py`'s `validate_vllm_url` already listed `::1`, but
  `eval/gate.py`'s `GateTask.judge_model` validator, `_parse_judge_url` (reused
  by `soup ship --judge-model` and the online-DPO trainer), and
  `commands/ship.py`'s own `--judge-model` check did not, so the same URL was
  accepted or refused depending on which code path validated it. All five now
  import `net_guard.LOOPBACK_HOSTS` instead of re-listing the hosts, so the set
  cannot drift per-site again. Covered in
  `tests/test_issue1548_judge_loopback_parity.py`.
