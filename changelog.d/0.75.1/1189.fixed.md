- **`soup train --find-lr` no longer fails when the training set is smaller than `--find-lr-steps`, or blames `--find-lr-output` for it (#1189 by @mohdUwaish59).** The live sweep takes one row per step; it stopped when the rows ran out (or when the loss went non-finite), but the report was written against the full schedule, so the run ended with `Invalid --find-lr-output: lrs and losses must have equal length`. The sweep is now sized to the rows over the same `--find-lr-start` → `--find-lr-end` range, with a line naming both numbers, and a divergence mid-sweep writes a report for the steps before it. The recommendation needs 4 points, so `--find-lr-steps` below 4 is rejected up front (the minimum was 2, which always failed), and a training set with fewer than 4 rows is refused before the model loads instead of falling back to a synthetic curve. An empty training set is refused the same way; it previously wrote a synthetic report and exited 0. `Invalid --find-lr-output` is now reported only for a problem with the output path.
