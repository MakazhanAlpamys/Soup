- **`training.warmup_ratio` dynamically resolves over actual optimizer steps instead of a precomputed estimate (#1431 by @kok-o in #1431).**
  Trainer wrappers previously turned `warmup_ratio` into fixed `warmup_steps` using raw dataset row counts before constructing the trainer. Under GRPO (where prompts repeat `num_generations` times), SFT with packing or multipack, and pretrain with packing, the trainer executed a different step count, causing warmup to shrink or cover the entire run so peak learning rate was never reached. All wrappers now pass `warmup_ratio` through via `resolve_trainer_warmup_steps` directly to `TrainingArguments(warmup_steps=...)`, letting transformers resolve warmup dynamically as `ceil(real_optimizer_steps * warmup_ratio)`.
