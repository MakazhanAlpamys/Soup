- `soup serve --device cpu` with the transformers backend now loads the model (and
  the base model under a LoRA adapter) on the CPU in float32. `_load_model` ignored
  its `device` argument and always passed `device_map="auto"`, so a visible GPU
  received the model anyway. `cuda` and `mps` keep `device_map="auto"` and float16;
  an explicit `--kv-cache-type bf16` / `f16` still sets the load dtype on every
  device. Behaviour change: with no `--kv-cache-type`, a CPU-only host now loads in
  float32 instead of float16. `--device` is now case-insensitive and any value other
  than `cuda`, `mps` or `cpu` is refused with exit code 2, and the help text says
  what each device does (#1478 by @drakeo338 in #1479).
