- ReLoRA restarts now follow the paper contract (#693 by @jagadeepmamidi in #1133): each fire merges the LoRA update into the base weight, reinitializes `lora_A`/`lora_B`, clears optimizer state when `relora_reset_optimizer` is set, and re-warms the learning rate. Behaviour break: `relora_steps` now requires explicit `quantization: none` because the schema default is `4bit`; previously a ReLoRA-only soup.yaml loaded and silently pruned. Embedding LoRA modules are skipped. Wrapped DeepSpeed/FSDP optimizers without `.state` are refused before merge even when `relora_reset_optimizer` is false. `relora_prune_ratio` is ignored with a warning at attach. Unsupported combos (`quantization` other than `none`, `stream_layers`, VeRA, DoRA, FSDP2 compile, MLX) are rejected at schema parse time instead of half-applying. The magnitude-prune helper now uses exact keep-count under ties. Merged base deltas remain in-memory until `soup merge` exports a dense checkpoint.
