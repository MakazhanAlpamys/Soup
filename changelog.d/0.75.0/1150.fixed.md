- **MCP execution now refuses a symlink planted at the run-log path when spawning a child (#1138 in #1150).** `ExecutionManager.execute()` opened `.soup/mcp-runs/<run_id>.log` with a plain `open(path, "ab")`, the one unguarded open left in `mcp_server/execution.py` after v0.75.1 moved the digest reader onto `O_NOFOLLOW`. A symlink at the log path redirected every byte the spawned child wrote to the link target. The open now goes through `utils.paths.open_no_follow` (#820), the helper the audit log already uses for appends, with mode `0o666` so a fresh log keeps the permissions plain `open()` gave; the refusal maps to the existing path-free `ExecutionError` and the child is never spawned. Windows rides the helper's reparse-point fallback unchanged. Pinned by a symlink-plant regression test plus a control asserting the normal path still hands the child a writable append-mode log.
