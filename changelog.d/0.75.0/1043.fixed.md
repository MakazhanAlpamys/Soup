- **Tasks that never apply `training.quantization` no longer record a quantised run (#795 by @Srinivasan8888 in #1043).** `distill`, `classifier`, `reranker`, `cross_encoder`, `prm`, `moe_lora_routing`, `unlearn` and `asr` load their models at checkpoint precision, yet accepted the default `4bit` (and an explicit `8bit`), stored it in the run's config, and let the VRAM pre-flight budget them as QLoRA jobs. For these tasks an unset `quantization` now resolves to `none`, and an explicit non-`none` value, `load_in_8bit`, or a 4-bit-only setting is refused at config load, naming the task. PRM also refuses a `lora` block it never reads (`lora.r: 0` is allowed), and the pre-flight budgets PRM, and the classifier family and ASR without their LoRA opt-in, as full fine-tunes. `docs/training.md` lists which tasks honour the field.
