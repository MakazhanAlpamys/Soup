- **Refuse a stale-green PR merge without forcing a rebase on every push to main (#1017).** A `pull_request` run pins `refs/pull/N/merge` at creation, so GitHub's green marks describe a `main` that may no longer exist (`strict` is off). `merge-freshness` rebuilds the merge on the runner (no write to the fork), fails on ruff F821 (the #763 `NameError` class) and when the merge-base is more than 10 commits behind `main` (the #853 class), and re-posts that check on every push to `main`. It does not flip `required_status_checks.strict` and does not re-run the 13-job matrix; `gh run rerun` still cannot refresh a frozen merge SHA, which CONTRIBUTING now says.
