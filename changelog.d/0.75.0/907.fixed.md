- **Six command modules, `utils/ship_verdict.py`, `mcp_server/registry.py`, and `commands/serve.py` carried a private copy of the terminal control-byte sanitizer instead of importing the shared one (#896).** v0.75.0 added `soup_cli.utils.terminal.for_terminal` (strip C0/DEL control bytes, then escape Rich markup) for the config loader's unknown-key report, but nine other call sites — `commands/adapters.py`, `data_canary.py`, `data_doctor.py`, `draft.py`, `infer.py`, `shrink.py`, `serve.py`'s `--auto-spec` pairing message, `utils/ship_verdict.py`, and `mcp_server/registry.py` — still carried a byte-identical `_CONTROL_STRIP_TABLE` under their own name, which is exactly how the config loader got missed for a release. All nine now import `for_terminal` (or the new strip-only `strip_control`, for the handful of call sites that feed non-markup contexts like `Text.append(..., style=...)` or an exception message escaped later downstream) from the shared module, and a new repo-wide test (`test_issue896_no_duplicate_terminal_sanitizer.py`) fails CI if a module besides `utils/terminal.py` ever defines `_CONTROL_STRIP_TABLE` again.
