- **`training.nvfp4` and three of the four `soup export --format torchao` schemes asked torchao for classes it does not have (#826 by @Srinivasan8888 in #1066).** `NVFP4Config`, `Int8DynActInt4Config` and `Float8DynActFloat8Config` are not exported by torchao 0.18.0, the newest release, so a Blackwell user who set `nvfp4: true` got a yellow advisory and a bf16 run, three export schemes could not build a config at all, and both refusals said "upgrade torchao" when there was nothing newer to upgrade to. Every class is now resolved through the module that defines it, so a rename fails naming the path; `training.nvfp4` uses `NVFP4TrainingConfig`, which quantises the forward and backward GEMMs, rather than an inference config that would only quantise weights after training. The four disagreeing torchao floors (`0.4.0`, `0.5.0`, `0.7.0`, `0.5`) become one constant, `inner_k_tiles` leaves the export allowlist because `Int4WeightOnlyConfig` raises `TypeError` for it, and a new `torchao-contract` CI job installs `.[qat]` so the names are checked against the real package instead of a stub that defined them.
