- **`data.remove_unused_columns: true` is refused at load, and the declared default is now `false` (#759 by @Srinivasan8888 in #1027).** The field declared `true` while all fifteen trainers hardcode `remove_unused_columns=False`, so a custom collator still receives the columns the model's `forward()` does not name: writing `true` deliberately got you `False`, silently, and the documented default was a false statement about what happens. `true` is now refused when the config loads, with a message naming the reason; `false` keeps working and means what it says; and no existing run changes behaviour, because the effective value was always `False`. The field is not deleted, since an unknown key is now a hard error and its own documentation told people to write it. Every shipped config — 174 recipes, 21 templates, 2 fetch examples and 8 examples — was measured through load, `model_dump()` and re-load before and after the change: zero failures either way.
