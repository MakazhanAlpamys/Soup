- **`data.mask_history` now does what it says (#761 in #1101).** The field was
  declared, validated and documented with a worked example, and read by no module
  outside the schema, so a config asking to train on the last turn trained on
  every turn. With `train_on_responses_only: true` it now keeps only the **last**
  assistant turn in the loss; earlier assistant turns are masked alongside the
  user and system turns that path already excludes, so it only ever removes
  tokens from the loss.
- **`data.mask_history` requires `data.train_on_responses_only: true` (#761 in #1101).**
  Without it every token trains, including the history the field asks to exclude,
  so the combination is refused at config load with a message naming both. That
  also rules out `train_on_messages_with_train_field`, which is already exclusive
  with `train_on_responses_only`.
