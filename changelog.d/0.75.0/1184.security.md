- **The adapter hot-swap now requires the `soup serve` tool token whenever one is configured (#1139 by @dchaudhari7177 in #1184).** `/v1/adapters/activate` and `/v1/adapters/deactivate` used to check only the Host/Origin guard, so on a non-loopback bind anyone whose `Host` header named the server could switch the served adapter, even though the operator had set `--tool-auth-token`: the token guarded the `/v1/tools/*` routes only. Since v0.75.1 `soup serve` refuses (exit 2) to bind a non-loopback host without a token, so an off-loopback server has one by construction, and the adapter routes now honour it. **This breaks an off-loopback hot-swap that sent no token:** send `Authorization: Bearer <token>`. For `soup loop watch`, pass the new `--tool-auth-token` or set `SOUP_TOOL_AUTH_TOKEN`; a `--detach` child gets the token through its environment, never its argv. A refused activation is now reported as a missing or rejected tool token instead of a bare failure. Loopback servers started without a token, and the inference routes, are unchanged.
