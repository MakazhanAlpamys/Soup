- **`stream_source: auto` now sees the physical RAM ceiling — the #622
  exit-137 OOM becomes a disk-tier fallback (#622 by @umran666 in #646).**
  The RAM-tier fit check compared the store against `MemAvailable * 0.70`
  alone, but a page-locked store is unevictable-class memory the kernel
  cannot swap or reclaim: a 16.10 GB store plus 3.11 GB resident on a
  30 GB host with 27 GB "available" was green-lit and then SIGKILLed
  before the first step, cold and warm cache alike, while the forced disk
  tier ran to completion on the same box. The tier now requires both
  ceilings — the existing dynamic fit and store+resident under 55% of
  TOTAL physical RAM (`RAM_TIER_PHYSICAL_BUDGET`); `auto` falls back to
  NVMe disk with a note naming the absolute ceiling and its figures, and a
  forced `stream_source: ram` over it is refused before sharding (and
  again at the exact-bytes validator) with the ceiling in the message
  rather than "free RAM", which no amount of freeing moves. The issue
  proposed sizing against `/dev/shm`; the thread's counter-analysis
  shipped instead, settled by the code: the store is allocated through the
  CUDA host allocator, never `shm_open`, and the 16 G tmpfs on a 30 GB
  host is systemd's 50% default — correlation, not mechanism. `statvfs`
  sizing would have forced large hosts with small custom mounts to disk
  and believed container `--shm-size` lies; `RLIMIT_MEMLOCK` is not
  enforced because driver-mediated CUDA pinning is not governed by it and
  a getrlimit gate would push every default-rlimit Unix box to pageable.
  Without psutil the total is unresolved and the budget unenforced, in the
  existing fail-loudly posture. Unit tests pin the reproduction's own
  numbers, the large-host control, the boundary and both refusal messages;
  four wiring tests drive the real pre-flight with mocked ceilings so the
  unthreaded-caller mutation dies by name. The live exit-137 reproduction
  needs the reporter's Linux host and is stated as unverified here.
  Closes #622.
