- **`soup adapters check` and `soup adapters diff` no longer crash on a bfloat16 adapter.** Both read the weights through `safe_open(framework="numpy")`, which cannot return bfloat16 (numpy has no such dtype), so an adapter saved from a bf16 run failed with `data type 'bfloat16' not understood`, or with "Corrupt or unreadable safetensors weights" in `check`. They now share one reader that parses the header with `read_header` and widens bfloat16 to float32 exactly (it is the top 16 bits of a float32); the other dtypes adapters store are read as before, a dtype numpy cannot hold (FP8, and the U16/U32/U64 tags `read_header` does not map) is refused as an unsupported dtype naming the tensor, and the size cap, tensor-count cap and symlink checks are unchanged. (#2063)
