- **`moe_lora: true` keeps a string `target_modules` and adds the MoE targets on top of it, as it already did for a list.** `resolve_moe_lora_targets` merged the MoE names into a list target (#1590) but replaced a string with the MoE list (`q_proj`, `k_proj`, `v_proj`, `o_proj` and the expert FFN names) plus the fused expert parameters, and a string means something to peft. `"all-linear"`, which `target_modules: auto` resolves to on qwen4_exp, adapts every linear layer but the output head, so a qwen4_exp base with `moe_lora` lost the Gated DeltaNet `in_proj_qkv` / `in_proj_z` / `in_proj_a` / `in_proj_b` / `out_proj`, the QSA indexer's `index_qk_proj`, the `shared_expert_gate`, the hyper-connection mixers and the PLE `key_proj` / `value_proj`: 10 adapted modules instead of 34 on a tiny two-layer model. Any other string is a regex peft full-matches against each module name, and it was dropped outright. Now `"all-linear"` (in any casing peft accepts) is kept as it is, since it already reaches every module the MoE names reach, and only the fused expert parameters are added. A regex becomes one regex, `(?:<your regex>)|(?:<the MoE names>)`, so peft adapts exactly what either half matches; a leading global flag such as `(?i)` stays with your half, and a regex that does not compile is refused at setup, naming `training.lora.target_modules`. The `ScatterMoE LoRA:` setup line says which of the two happened. Lists are unchanged, and so is every run without `moe_lora`. This applies to every resident trainer; layer streaming resolves its targets on its own path, which this does not change. (#PENDING)
