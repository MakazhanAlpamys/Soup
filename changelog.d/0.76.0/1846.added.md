- **DPO runs natively on Apple Silicon: `task: dpo` with `backend: mlx` (#1846 by @dryn85-max).**
  It was refused at config load because the MLX wrapper was scaffolding. Soup now runs its own
  MLX loop with TRL's default sigmoid loss and `training.dpo_beta`. Rows are tokenized exactly as
  TRL 0.29 does, so the same `soup.yaml` trains on the same tokens on either backend. No second
  model is loaded: reference log-probs are precomputed from the base model. `training.seed` and
  `training.data_seed` are honoured, and the vocabulary head runs in checkpointed chunks to keep
  long pairs in memory. On an M4 Pro, Qwen2.5-0.5B-Instruct trained 3.5x faster than TRL on MPS
  with the same bf16 weights, at about half the process memory. Pairs whose `chosen` equals their
  `rejected` are skipped with a count. Try: `soup train --config soup.yaml` with `task: dpo`,
  `backend: mlx` and `base: mlx-community/Qwen2.5-0.5B-Instruct-4bit`.
